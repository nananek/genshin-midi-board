# 設計判断

## 1. 結論

**RP2040 QFN-56 + CH345T + 4 層**を採用します。USB デバイス側は native USB（PC HID）と CH345T（iPad MIDI）の 2 系統です。PC と iPad は物理的に別ポートにし、片方が未接続でももう片方は動作する構成にします。

## 2. 採用構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| MCU | RP2040 QFN-56 | 0.4 mm ピッチで外周パッドを外へ逃がせる。PIO-USB、native USB、UART1 を 1 個で使える |
| USB-MIDI | CH345T | UART 31250 と USB-MIDI のブリッジ。RP2040 に MIDI デバイススタックを載せずに済む |
| 基板 | 4 層 | GND と +3V3 のプレーンを保ちながら、標準ビアだけで配線できる |
| USB-A | PIO-USB ホスト | RP2040 の PIO で USB ホストを実装する。外付けホスト IC が不要 |
| USB-C ×2 | native USB と CH345T | PC と iPad を別ポートに分け、相互の影響をなくす |

## 3. 各判断

### RP2040 を選ぶ

RP2040 の QFN-56 は 0.4 mm ピッチで、外周パッドを外側へ逃がすだけで全ピンを引き出せます。Raspberry Pi Pico は同じ QFN-56 を 2 層で使っており、4 層なら GND プレーンを保ちながら標準ビアだけで配線できます。今回の基板は Pico より面積が大きく、部品点数も少ないため、4 層で十分な余裕があります。

今回の用途に必要なものは揃っています。

- PIO-USB ホスト（Pico-PIO-USB が RP2040 に対応）
- native USB デバイス（TinyUSB）
- UART1（CH345T 用）
- 30 GPIO（スイッチ 5 個、LED、UART、PIO-USB、CH345T で足りる）
- 264 KB RAM（MIDI キューと HID 状態に十分）

ファームウェアは pico-sdk で実装でき、ピンは GP4/5、GP12/13、GP27/28/29 を使います。

### USB デバイスを 2 系統に分ける

PC へは NKRO HID、iPad へは USB-MIDI を出します。1 つの USB ポートで両方を兼ねると、接続先によって見え方が変わり、PC と iPad の同時接続もできません。native USB と CH345T に分けると、PC 側が未接続でも iPad へ MIDI は流れ、iPad 側が未接続でも PC へ HID は流れます。

### Type-C を 29 mm ピッチで離す

2 本の USB-C を同じ上辺に置きますが、中心間を **29.0 mm** にします。コートヤード間の隙間は 18.36 mm で、一般的な Type-C ケーブルの樹脂部（片側 6 mm 程度）を考えても 6 mm 以上の余裕があります。10 mm ピッチにすると樹脂部が干渉するため、この間隔は崩しません。USB-A は下辺に置き、キーボードのケーブルと PC/iPad のケーブルが上下に分かれるようにします。

### 標準ビアだけで配線する

通常のビアを **0.5 mm 径 / 0.3 mm ドリル**にし、最後の 1 本だけ **0.45 mm 径 / 0.25 mm ドリル**を使います。Type-C の A7/B7 も、パッド内ビアではなくパッド外のビアへドッグボーンで逃がします。0.15/0.2 mm ドリルは使いません。

0.15 mm ドリルを 1 本でも入れると、JLCPCB の最小ビア、プラグ処理、4-Wire Kelvin テストなどのオプションが付きます。5 枚の試作では、これらのオプション料金が基板本体より大きくなります。via-in-pad も同じく樹脂充填やプラグ処理の対象になるため、使いません。

### CH345T の入手性

CH345T の在庫が少ない場合は、RP2040 をもう 1 個使って UART 経由で MIDI デバイスを実装する案があります。ただし RP2040、flash、水晶、LDO が 2 組必要になり、BOM と配線が増えます。CH345T の在庫を発注直前に確認し、確保できない場合の代替とします。

## 4. 採用しなかった理由のまとめ

- 6 層は今回のコスト方針に合わない
- via-in-pad と 0.15 mm ドリルは JLCPCB のオプション料金を誘発する
- Type-C の近接配置はケーブルの樹脂部で干渉する
- 2 個の MCU 構成は USB-C の位置制約とファームウェアの二重管理が残る

## 5. 処理能力とコスト

今回の用途で RP2040 の処理能力が足りるかは、CPU の汎用性能より「USB ホストと USB デバイスを同時に動かせるか」で決まります。

RP2040 の負荷は次のように分かれます。

- core1: PIO-USB ホスト。USB のビットタイミングは PIO が担当し、CPU はパケット処理と MIDI パースを担当する
- core0: native USB の NKRO HID、スイッチ、LED
- UART1: CH345T へ 31250 bps で生 MIDI を流す。割り込み負荷は小さい
- USB-MIDI デバイス側の処理は CH345T が担当するため、RP2040 に MIDI デバイススタックは不要

MIDI の Note On/Off は高々数百イベント/秒、HID レポートも 1 kHz 程度です。120 MHz のデュアル Cortex-M0+ と 264 KB RAM で足ります。DSP も浮動小数点も使いません。

コスト面では、4 層化と標準ビア化で基板とオプション料金を抑えられます。5 枚程度の試作では、部品単価の差より、6 層、via-in-pad、0.15 mm ドリルといったアドバンスオプションを外す効果のほうが大きくなります。

確認事項は 2 つです。

- PIO-USB ホストと native USB デバイスを同時に動かしたときの取りこぼしを実機で確認する
- RP2040 の長期供給を定期的に確認する

flash は W25Q128（16 MB）を載せていますが、ファームウェアは小さいため、コストを詰めるなら W25Q64 や W25Q32 でも足ります。
